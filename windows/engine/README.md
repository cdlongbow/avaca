# AVACA pinned Flutter Windows engine

AVACA's Windows release bundles use the two binary artifacts in this
directory. They are built from the Flutter 3.44.8 engine with the small patch
in [`flutter_windows.patch`](flutter_windows.patch): the Windows EGL manager
requests ANGLE DirectComposition for HWND surfaces and fails closed unless
`eglQuerySurface` reports `EGL_DIRECT_COMPOSITION_ANGLE == EGL_TRUE`.

The pinned engine is intentional. On the supported Windows setup, the stock
Flutter 3.44.8 ANGLE HWND sequential swap-chain path returns
`DXGI_STATUS_OCCLUDED` and presents a white client area. The pinned engine uses
the DirectComposition path and has been verified with the same AVACA bundle.

  `0cd610717bde95fd88343c64f81c11ba4e5c0010`
- ANGLE DEPS revision:
  `84027aca9b71c9ba335bd000dad1107b8810a511`
- Engine dependencies: the exact `DEPS` file at that framework commit,
  synchronized by `gclient` before the build
- Target: Windows x64, release, host release
- Build configuration: `out/host_release/args.gn` generated by Flutter's
  3.44.8 engine GN files with `is_official_build=true`, `is_debug=false`,
  `flutter_runtime_mode="release"`, `target_os="win"`, and `target_cpu="x64"`
- Build host: Visual Studio Community 18.8.2, MSVC 14.51.36231, Windows SDK
  `10.0.26100.0`, with `DEPOT_TOOLS_WIN_TOOLCHAIN=0`
- The local engine checkout used the 3.44.8 toolchain script's SDK selection
  adapted from unavailable `10.0.22621.0` to installed `10.0.26100.0`; the
  local SDK also lacks the optional debugger `dbghelp.dll`, so the temporary
  build-host script skipped copying that optional file. Neither adaptation
  changes the shipped engine source or runtime behavior.
- `flutter_windows.dll` SHA-256:
  `7109076e985b22c4028fe7c59b90cbfb105290f479611cf44d86a8a794430395`
- `flutter_windows.dll.lib` SHA-256:
  `ccda50dd560bf250d3dcaca740aee81da82c4b64fa9390bb7aa2decc7c678387`
- The import library must remain paired with `flutter_windows.dll`; CMake
  refuses a partial pair and copies both into the Flutter ephemeral output
  before the runner and plugins link.

Do not replace either binary without updating this record with the exact
source/dependency revision, patch, toolchain, and SHA-256 values, then rerun
the Windows A/B and release-bundle checks.
